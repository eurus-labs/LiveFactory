# ADR-0001: Run each attempt as a static systemd template unit

- Status: Accepted
- Date: 2026-10-19
- Applies to: Ring 0 and later, while execution stays on one host

## Context

Ring 0 runs one core and one worker on one Linux host. Draft v0.2 carried a lease,
heartbeat, epoch and fencing protocol designed for workers on other machines. On one
host, the operating system can already track, time out and kill processes. The worker
also runs arbitrary code, so it must run under a separate principal with a sandbox.

Starting a transient unit from core would require the right to start any unit as any
user, which is close to root. A `systemd-run --scope` does not help: a scope only manages
a process created elsewhere, inherits the caller's environment, and cannot use the
`systemd.exec` sandbox options.

## Decision

- Each attempt runs as `factory-worker@<attempt_id>.service`, an instance of a static
  template unit. The attempt ID is a ULID generated by core and matched against
  the canonical ULID form `^[0-7][0-9A-HJKMNP-TV-Z]{25}$`, in core and in the polkit rule.
- The template sets `User=`, the sandbox options, `PrivateNetwork=yes`,
  `RuntimeMaxSec=` as a hard ceiling, `KillMode=control-group`, and
  `BindsTo=` plus `After=` on the core service.
- A polkit rule allows the core principal to `start` and `stop` only units matching
  `factory-worker@*.service`.
- A privileged `ExecStartPre=+` claims the attempt by creating a run-once marker in a
  directory no worker can write, and fails if the marker exists. Starting an inactive unit
  again therefore cannot run the attempt a second time.
- The unit hides `/var/lib/factory` behind an empty read-only tmpfs and bind-mounts back
  only the current workspace, the assignment (read-only) and the gateway socket, so
  attempts sharing one UID cannot read each other's files.
- Core enforces each stage's `execution_timeout` by stopping the unit; `RuntimeMaxSec` is
  the backstop if core hangs.
- Core uses the systemd watchdog, notified from its main dispatch loop.
- The unit file and the polkit rule belong to the protected set
  ([ADR-0005](0005-self-improvement-scope.md)). Only the operator changes them.
- Ring 0 has no lease, heartbeat or epoch fields. They are added when execution leaves
  the host.

Sketch, to be verified with `systemd-analyze verify` and `systemd-analyze security`:

```ini
[Unit]
BindsTo=factory-core.service
After=factory-core.service

[Service]
Type=exec
User=factory-worker
ExecStartPre=+/opt/factory/bin/claim-attempt %i
ExecStart=/opt/factory/bin/worker-host --assignment /run/factory/assignment
RuntimeMaxSec=2h
KillMode=control-group
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
PrivateNetwork=yes
TemporaryFileSystem=/var/lib/factory:ro
BindPaths=/var/lib/factory/attempts/%i/workspace
BindReadOnlyPaths=/var/lib/factory/attempts/%i/assignment:/run/factory/assignment
BindReadOnlyPaths=/run/factory-gateway/gateway.sock
```

```js
polkit.addRule(function(action, subject) {
  if (action.id == "org.freedesktop.systemd1.manage-units" &&
      subject.user == "factory-core" &&
      /^factory-worker@[0-7][0-9A-HJKMNP-TV-Z]{25}\.service$/.test(action.lookup("unit")) &&
      ["start", "stop"].indexOf(action.lookup("verb")) >= 0) {
    return polkit.Result.YES;
  }
});
```

## Consequences

- Duplicate dispatch is harmless: starting an active unit is a no-op, and starting an
  inactive one fails at the run-once claim.
- When core stops, systemd stops every bound worker, so no worker outlives the core that
  started it. After a restart, core reconciles open attempts instead of reattaching.
- Core gains exactly one privilege, and acceptance scenario T15 must prove it cannot use
  any other.
- A per-stage timeout cannot live in a static unit, hence the two layers.
- The design depends on systemd and polkit. Another platform needs a new adapter and new
  boundary tests.
- A hung core with a live process is caught by the watchdog, not by a lease.
- A fixed `User=` means attempts share a UID. This is acceptable with one worker at a
  time; `DynamicUser=yes` is the candidate once attempts run concurrently.

## Alternatives considered

- **Lease and heartbeat on one host**: duplicates what the OS already provides and adds
  states and tests without catching a failure the OS misses.
- **Transient units from core**: needs broad unit-management rights.
- **`systemd-run --scope`**: no sandbox options and an inherited environment.
- **Plain child processes with `setuid`**: core would need root or capabilities, and
  cleanup of process trees would be custom code.
